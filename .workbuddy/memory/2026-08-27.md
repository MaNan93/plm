## Verilator + GTKWave 仿真验证（--sel-mode comb）

- 用 `tools/plm_gen.py --config config --sel-mode comb` 重新生成 RTL，Verilator 5.050（conda env: `C:/Users/man/miniforge3/envs/verilator/Library`）仿真通过：TB_RESULT PASS，4 mode 路由 + SAFE 态 + one-hot + 复位脉冲全 0 错误，4us 仿真 0.18s。
- **本机 Verilator 工具链三大坑**（已固化到 `run_sim.sh`）：
  1. 包内 `verilated.mk` 硬编码 conda-forge CI 机器的 cl.exe 路径（本机无 VS2022），`verilator --binary` 自动构建必失败，且会把 MSVC 风格 CXXFLAGS/PCH 写进 makefile。
  2. 自带 mingw g++ 16.2 的静态 libstdc++ 损坏：`-O1/-Os` 下链接报 `std::__cxx11::basic_string` move ctor undefined（`-O0` 正常）→ 必须用 `-O0` 一步编译链接。
  3. `crt2.o/default-manifest.o` 在 `x86_64-w64-mingw32/sysroot/usr/lib`（gcc 搜索路径里没有），需 `-B` 指向该目录；AR 用 `Library/x86_64-w64-mingw32/bin/ar.exe`。
- 附带坑：本环境 bash 的 `rm` 被安全删除 shim 包装，verilated.mk 里的 `rm -f` 会因 shim 报错中断 make；绕法：不走 make，直接 g++ 一把编。
- GTKWave 启动必须把 `C:/Users/man/gtkwave/bin` 加进 PATH，否则 SVG loader DLL 依赖缺失直接 bail out。
- 产物：`obj_dir_comb/plm_sim.exe`、`waves.vcd`（707KB）；重建入口 `run_sim.sh`。
